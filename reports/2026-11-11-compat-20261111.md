## 死路与决策

- 试过用版本号判代际（把 `docs/upgrade-guide/v0.2.1-rc.2` 当发版边界），不行，因为那只是文档目录名：npm 最新 0.2.2-rc.1 仍是老一代，按版本号会把当前桌面端判反。改成按工具清单与 `agentTeams.spawnTeammate` 能力判断。
- 决策：0.2.4 同时支持两代，不做只写新 API 的版本。依据：新一代没有 npm 版本号，只写新 API 会让当前宿主立刻失效。推翻信号：新一代发版且宿主明确拒绝老配置时，删掉老分支指引。
- 决策：没开 Team 时先给会话开关、再给装包命令，且命令只标注给 ≤0.2.2-rc.1。依据：`RETIRED_BUNDLES` 会让 app-boot 删掉该包，新宿主上装了白装。推翻信号：新版宿主重新随 profile 包下发 Team。

## 未决与下一步

- 用户装 0.2.4 并重启桌面端后，跑一次 `/lead-mode` 核老一代输出未变（应仍是 `已挂载（maxMembers 8）`）。命令：`dsh plugin --profile desktop add dsh-lead-mode@0.2.4`。
- 新一代发版时：把 `engines.dsh` 与 `dshTarget` 推进到那一版，删掉老一代装包指引，并把 spec 里的「未发版」标注去掉。
- 明确不做：不改宿主行为；不为两代拆成两个包；不给新一代凭空安版本号。

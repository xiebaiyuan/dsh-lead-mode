# 多轮长程控制回路

仅在预计 ≥2 轮派单/验收或跨模块推进的长程任务中读取；单轮任务（一人一轮完成、无跨轮合流）跳过。

## 1 何时启用

满足任一条即启用该控制回路：

- 预计需 ≥2 轮派单或验收才能交付。
- 改动跨多个模块，存在先后依赖或合流节点。
- 任务已进入第 2 轮，主目标判据尚未全部通过。

单成员一轮完成、纯资料查询或无跨轮状态的小改动，不启用。

**开局模型编队**：启用长程控制回路时，开局调一次 `list_subagent_models()`，对照 `references/model-roster.json` 与 `references/member-models.md` 排出「角色 → 实返路由」编队（清单仅 1 条时全员继承 Lead 同款），并在开工对齐时同步给用户。按「两头重、中间快」推进：高风险开局规划或审美用 Tier 1 定契约，主体实现用 Tier 2 并行带绿交卷，只读查证用 Tier 3，终局用异构模型独立验收。

完成标准：开工前已判定「启用 / 不启用」；启用时已列出主目标判据编号 `#1..#M` 与开局模型编队。

## 2 主目标判据进度账（N/M）与工具边界

开工前将主目标拆为 `M` 条可验证判据（编号 `#1..#M`），每条写明核验命令或可复现判据。派单与工作日志的状态摘要均标明级别（主目标 / 支撑 / 枝节）与服务判据 `#k`；支撑活另写明阻塞哪条主目标判据与停止线，解除阻塞即止。

- **一屏目标宪章（`.scratch/<effort>/anchor.md`，硬限 ≤30 行，不进 git）**：开局获用户确认后由 Lead 控制面落盘一次（或交开局首位成员顺手落盘，严禁碰业务文件），只写 4 块不滚动的硬锚：**版本号与一句话终极目标（如 `v1`）**、**明确不做项（Non-Goals / 红线）**、**冻结主目标判据 `#1..#M`（含可执行核验命令原文）**、**开局模型编队**。严禁写入每轮进度流水或总结，与 `worklog`、`leftovers`、`team-digest` 职责互不重叠。
- **版本化与接受纠正优先**：用户明确说「之前错了/改成 X」或中途变更目标、删减判据时，立即放弃旧方向、不辩护；将 `.scratch/<effort>/anchor.md` 升级版本（`v1 → v2`）并单行写明变更项与作废判据，同时用 `send_message` 向所有活跃成员广播新版本号与变更行。重锚一律只认最新版本。
- **每轮首行锚点脉冲头**：每轮醒来回复第一行先打一行状态头：`[锚点 v1｜进度 N/M｜未过: #2,#3｜连滞: 0/2｜下步: ...]`，在上下文顶部持续刷新注意力。

每轮醒来先统计已通过的主目标判据数 `N/M`：

- 只有带证据（可粘贴命令 + 输出摘要，或独立验收核验结果）的判据才计入 `N`。
- 口头声称「已通过」「已修好」不计入 `N`。
- 未达成的主目标判据与阻塞它们的支撑活排在最前；枝节回报直接记入 `.scratch/<effort>/leftovers.md`，不计入 `N/M`、不进并行队列。

轻量工具与落盘边界（不造第二份正文）：

| 工具 / 文件 | 怎么用 | 边界 |
|---|---|---|
| `todo_write` | 可选，一判据一条，轻量跟踪 `#1..#M` 的 `N/M` 进度 | 只放主目标判据；不将枝节或临时想法写入 todo |
| `create_goal` | 仅在用户明确要求无人值守长程推进时启用 | 普通多轮协作不默认开启；未经用户授权不调用 |
| `.scratch/<effort>/anchor.md` | 开局写死的目标宪章（≤30 行，需求变更升 `vN`） | 只放目标、Non-Goals、冻结 `#1..#M` 与编队，不写每轮流水 |
| `.scratch/<effort>/worklog-<mate>.md` | 成员滚动进度与死路记录 | 每位成员一份，不另开每轮总表 |
| `.scratch/<effort>/leftovers.md` | 枝节与降级验收台账 | 五列表格，收尾报数 |
| `reports/<YYYY-MM-DD>-<effort>.md` | 收尾一次成型的团队汇总（见 `team-digest`） | 不新增 `reports/status-*.md` 或独立 `acceptance.md`（遵循 ADR 0001，防止多份正文漂移） |

完成标准：开局已落盘 ≤30 行 `anchor.md` 且每轮首行带锚点脉冲头；每轮醒来均报出当前 `N/M`；todo 中仅含 `#1..#M`；磁盘不新增 `reports/status-*.md` 或独立 `acceptance.md`。

## 3 分层验收与验收预算

验收分两层，避免每改一个局部模块就全量重跑：

| 层次 | 什么时候跑 | 跑什么 | 默认次数上限 |
|---|---|---|---|
| 局部验收 | 每个中间轮次结束 | 受影响子集：目标单测、局部 check、本块文件 `git diff --stat` | 每轮按块跑，过单即放行 |
| 全量验收 | 关键合流节点、最终交货前 | 全套测试、全量 check、跨模块回归与最终 diff | 默认最多 **2 次**（合流 1 次 + 最终独立验收 1 次） |

五条护栏：

1. **判据全过即停**：任务单既有判据 `#1..#M` 全部通过且无新发现的阻塞性主目标缺陷，立即收工，不顺手加检。
2. **独立验收只核既有判据**：最终独立验收成员只核任务单既有判据与主目标直接相关回归；验收中发现的枝节或范围外改进按级记入 `.scratch/<effort>/leftovers.md`，不扩大验收范围、不触发额外返工。
3. **降级验收可写走查步骤**：全量视觉回归、逐条界面走查等难以单条命令覆盖的项，可延后记入 `leftovers.md`；「后面怎么查」列除可粘贴命令或文件路径外，可写可复现走查步骤（**对象 + 入口 + 判据**）。三类均写不出时不许降级。
4. **增量复验不占全量预算**：实现者带绿交卷后的独立验收须一次扫全并附四件套缺陷包；返工交回且增量 diff 局限在缺陷窄范围时，复用同一验收成员只复跑失败判据与直接受影响回归，该次增量复验不计入全量最多 2 次预算。
5. **独立验收防静默改标**：验收成员核对 `git diff` 时须对照 `.scratch/<effort>/anchor.md` 原判据，显式排查实现者是否通过删测试、弱化断言、跳过用例或篡改契约换取命令全绿；发现改标直接判阻塞打回。

完成标准：中间轮次不跑全量；全量验收次数 ≤2（窄范围增量复验不占预算）；独立验收一次扫全、核实未改标且不因范围外发现加派返工单。

## 4 连续 2 轮无增长：先升模型，再止损问用户

**触发条件**：连续 2 轮派单/验收结束时，主目标判据通过数 `N` 没有增长（`N` 停在同一个数）。出现「修 B 坏 A」震荡（总通过数 `N` 持平或倒退，或同一根因反复打回）同样按无增长计数；先要求输出 5 行根因诊断、禁止盲改，满足连续 2 轮无增长即按下方三步升级或止损。

- **反支撑膨胀熔断**：同一判据 `#k` 下的前置支撑连跑超过 **2 轮**仍未解除阻塞，或连续 2 轮仅支撑任务完成而主目标 `N` 零增长，视同无增长并立即停手复核（判断是否需换方案或收缩支撑边界）。
- **5 轮中期战报检查点**：长程任务跑满 **5 轮**仍未达成全部主目标（即使每轮有缓慢增长），强制向用户发一次 5 行中期战报（当前 `N/M`、已耗轮次、剩余最大风险、继续还是缩范围），防无人看管空转。

按以下三步顺序执行，不跳步、不原地无限重试：

1. **停枝节、查授权模型清单**：立即停止新派任何枝节单。调用 `list_subagent_models()` 检查当前会话授权清单里是否有比现用执行成员更强的模型（如 Opus 等旗舰推理模型，或更高推理档 `high` / `max`）。`provider`、`model`、`reasoning_effort` 逐字抄写 `list_subagent_models` 返回原文，不编造 id；两层开关与会话钉住规则见 `references/member-models.md`。
2. **有更强模型 → fresh 接手卡点跑 1 轮**：将卡住的主目标判据 `#k` 或阻塞支撑整理为交接文档（或窄任务单，写明已排死路与绝对路径），用 `subagent`（`fresh`，不用 `subagent_fork`，因为 fork 不带模型参数且复制 Lead 历史，拿不到前任细节）切至更强模型跑 1 轮，验收并核查 `N` 是否增长。若切更强模型跑完 1 轮后 `N` 增长（卡点打通），剩余常规实现立刻回落至主力执行档（见 `references/member-models.md` 与 `references/model-roster.json`），不持续占用旗舰档跑常规收尾。
3. **无更强模型，或切后仍无增长 → 停派问用户**：授权清单无更强模型（例如仅返回一条跟随父模型，或现用成员已是清单最高档），或按第 2 步切更强模型跑完 1 轮后 `N` 仍无增长时，立即停派新单，向用户汇报四项并等拍板：
   - 当前进度 `N/M` 与卡住的判据 `#k`；
   - 已尝试路径与已排死路（写明是否已尝试切更强模型、使用哪一对路由或为何无法切换）；
   - 2–3 个可执行取舍选项：降范围（砍哪条判据）/ 调判据 / 用户人工介入 / 在设置页「子智能体 → 模型选择」授权更强模型后新开会话重试；
   - 未解决项的当前风险。

与主文件 §12「难度升级：一次同模型专家」分工：同模型专家用于单件设计、审美或架构判断力任务退回两次后出方案、不动手；本节用于多轮长程中 `N` 停滞时升级执行成员模型直接突破卡点，或在无更强选项时止损请示用户。

完成标准：连续 2 轮 `N` 无增长时，先调 `list_subagent_models` 决定切模型或止损；切后仍停滞或无更强模型时，带着四项汇报停手问用户，不空转第 3 轮。

## 5 Lead 上下文压缩后重锚

长程任务多轮运行后，Lead 自身会话同样会被自动压缩，早期目标、判据编号和已排除枝节可能仅剩摘要，而且模型被压缩后往往意识不到记忆已失真。

遇到以下三个机械心跳触发点之一（每满 **3 轮**派单/醒来、**阶段切换**如规划→实现→合流→终审、或会话发生压缩/隔轮发现上下文变薄），先执行以下三步重锚，再决定下一轮派单：

1. **重读目标宪章与核主目标判据（N/M）**：先读 `.scratch/<effort>/anchor.md` 最新版本（`vN`），核对终极目标、Non-Goals 与 `#1..#M` 哪些已带证据通过、哪些未过、是否已连续 2 轮无增长（启用 `todo_write` 时对照 todo、任务板与各成员工作日志头部状态摘要）。
2. **核任务板在办项**：调 `team_task_list` 对照在办任务、阻塞关系与最新 `revision`，确认当前仍在阻塞主目标的支撑活。
3. **核遗留清单**：派只读成员核对 `.scratch/<effort>/leftovers.md` 现状（仅缺一两条记录时可直接核查），确认已归入枝节的项，避免压缩后将已降级枝节重新派为新单。

**跨会话无缝冷启动**：遇到宿主重启、上下文过长或需新开会话刷新模型授权清单（会话钉住）时，新会话 Lead 只需读 `.scratch/<effort>/anchor.md` + `.scratch/<effort>/leftovers.md` + 最新 `worklog-<mate>.md` 头部状态摘要，即可接续战局，不重翻旧聊天记录。

硬边界：重锚完成前不派新单；只按主目标与阻塞支撑排优先级，不顺着最近一条枝节通知往下挖。

完成标准：每次心跳触发或压缩醒来后，先重读 `anchor.md` 并报出当前 `N/M`、剩余未过判据 `#k` 与在办主目标/支撑任务，再发出下一轮派单。

## 6 多轮样例：3 轮跨模块改造

场景：给导出模块增加 CSV 编码修复与断点续传，跨 `parser/`、`exporter/`、`ui/` 三个目录。

开工定下 3 条主目标判据（`M = 3`），用 `todo_write` 记 3 条（不放枝节）：

- `#1`：`parser/` 正确识别 UTF-8 BOM 与 GBK 输入（`npm test -- test/parser.test.mjs` 全绿）
- `#2`：`exporter/` 中断后可按偏移量续传且无重复行（`npm test -- test/exporter.test.mjs` 全绿）
- `#3`：整套集成测试与打包检查全绿（`npm test && npm run check` 通过，且最终 diff 无范围外改动）

### 第 1 轮：判级、并行派主目标、拦下枝节

- 拆出 4 块活：
  - `task-1`（主目标｜服务 `#1`）：改 `parser/`。
  - `task-2`（主目标｜服务 `#2`）：改 `exporter/`。
  - `task-3`（支撑｜阻塞 `#2`｜停止线：提供临时断点文件读写 helper 即止，不重构存储层）：补 `shared/checkpoint.mjs`。
  - `ui/` 导出进度条小屏文案截断（枝节）：写作用域虽与前 3 块不重叠，但先按 §12 判级为枝节，**不进并行队列**，直接记入 `.scratch/20261124-export/leftovers.md`：
    - 编号 1｜导出进度条小屏文案截断｜不影响主目标验收｜对象：导出弹窗进度条；入口：打开导出页并将窗口宽度缩至 360px；判据：进度百分比与按钮文案不重叠、无截断｜发版前
- 派单：`task-1` 与 `task-3` 无依赖，一次并行派给 `parser-dev`、`infra-dev`；`task-2` 标 `blocked_by: ["task-3"]`。派完结束回合。
- 醒来核进度：`parser-dev` 交卷且局部测试通过（`#1` 通过），`infra-dev` 解除阻塞并按停止线收手。当前 `N/M = 1/3`（本轮有增长：`0 → 1`）。派 `exporter-dev`（普通档模型）执行 `task-2`。

### 第 2–3 轮：局部失败、连续 2 轮无增长触发模型升级

- **第 2 轮醒来**：`exporter-dev` 交回 `task-2`，局部单测 `test/exporter.test.mjs` 在并发重入场景失败，`#2` 未过。当前 `N/M = 1/3`（第 1 轮无增长）。Lead 明确指出失败用例与报错，重发窄单给 `exporter-dev` 返工。
- **第 3 轮醒来**：`exporter-dev` 返工后仍卡在同一边界条件，`test/exporter.test.mjs` 依旧红，`#2` 未过。当前 `N/M = 1/3`（**连续 2 轮无增长**，触发 §4 升级止损）。
- Lead 执行 §4 三步：
  1. 停新派任何枝节单；调 `list_subagent_models()`，发现清单除现用普通档模型外，还授权了旗舰推理模型（如 Opus `high` 档，原文抄写 `provider` / `model` / `reasoning_effort`）。
  2. 要求 `exporter-dev` 补完工作日志并写交接文档 `.scratch/20261124-export/handoff-exporter-dev-1.md`（含已排死路），`release` `task-2` 后用 `subagent`（`fresh`）切旗舰模型派 `exporter-dev-r2` 接手跑 1 轮。
  3. `exporter-dev-r2` 一轮定位偏移量锁竞争，局部测试 `test/exporter.test.mjs` 全绿，`#2` 通过，进度升至 `N/M = 2/3`。（若清单无更强模型，或 `exporter-dev-r2` 跑完后仍停在 `1/3`，Lead 直接停派并按 §4 第 3 步请示用户拍板。）

### 收尾：最终独立验收，过即停

- 派未参与实现的只读成员 `verifier` 执行最终独立验收（全量预算 1/2）：只核 `#1`、`#2`、`#3` 与主目标直接回归，运行 `npm test && npm run check` 与 `git diff --stat`。
- `verifier` 回报 `#1/#2/#3` 全部通过（`N/M = 3/3`），附带提到 `exporter/` 有一处老日志格式不够整齐。Lead 判为范围外枝节，记入 `leftovers.md` 编号 2，不触发额外返工，直接按 `team-digest` 写团队汇总并交货；收尾报数：`主目标：达成（3/3）`，遗留 2 条在 `.scratch/20261124-export/leftovers.md`。

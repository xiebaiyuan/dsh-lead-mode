# 团队汇总：写什么、给谁看

成员各交一段收尾消息，各写一份工作日志。收尾时没人合并，用户得自己翻 N 条通知，过一周想回看还得重新调查一遍。这份 skill 产出那份合并物。
主要用途是日后回看。当场看懂是它的副产物，不要为了「当场好看」多写。

## 什么时候写

给最终答复之前判断，满足一条就写：

| 条件 | 说明 |
|---|---|
| 本 effort 有 2 个以上成员 | 一人一段就要合并，否则用户得自己拼 |
| 跨 2 轮以上 | 同一成员多轮、或换过续作成员，过程散在多轮里 |

不写的情况：只有一个成员一轮干完、只查了资料没改动、纯问答。
别为一次调用产出一份报告。

## 写到哪

`reports/<YYYY-MM-DD>-<effort>.md`，相对仓库根，单一路径。

- `<effort>` 用 `.scratch/` 下那个目录名，和工作日志同源，别另起一套命名。
- 不新增目录层级，不加 `-v2`、`-final` 这类后缀。
- 同一 effort 同一天只写一份。收尾时一次成型，不追加、不做增量、不设「晋升」步骤。
- 想进笔记库，自己给 `reports` 建软链，不要改路径。
- 目录不存在就建。建不了（只读挂载等）就在最终答复里说清楚，别悄悄丢。

## 六块骨架

六块标题写死：不改名、不合并、不跳块。某块没内容就写「无」。

| 块 | 标题 | 写什么 |
|---|---|---|
| 1 | 结论 | 做完了什么、能不能用，一到两句。不放清单 |
| 2 | 谁干了什么 | 表格：成员 / 交付物 / 状态 / 产物指针 |
| 3 | 验收证据 | 一条一行：可粘贴的命令 + 输出摘要 + 是谁复跑的（独立验收成员跑的最高级，只有实现者跑的不算） |
| 4 | 偏离与未验证 | 偏离规格的、只口头声称没证据的；这一块末尾是未验证清单 |
| 5 | 死路与决策 | 结论级死路一行一条；不可逆决策一条一记录 |
| 6 | 未决与下一步 | 还没定的、下一轮第一件事、明确不做什么；遗留只写编号 + 一句话 + 清单路径，没有就写「遗留：无」 |

照这个骨架填，标题一个字都别改：
```markdown
# 团队汇总 · <effort>

## 结论

## 谁干了什么

| 成员 | 交付物 | 状态 | 产物指针 |
|---|---|---|---|

## 验收证据

## 偏离与未验证

### 未验证清单

## 死路与决策

## 未决与下一步
```

第 4 块放偏离规格的结论和没证据的结论，不许混进第 1、2、3 块；这一块末尾的未验证清单只写「谁、什么没验、缺什么证据」，不能拿清单替代这一块。

### 第 2 块的状态列

只有五个取值，别扩展：

| 取值 | 什么时候用 |
|---|---|
| 完成 | 交付物在，独立验收也核过 |
| 未验证 | 交付物在，但只有口头声称，没有可复跑的证据 |
| 卡住 | 没干完，阻塞点还在 |
| 被打断 | 被 `interrupt_agent` 或用户中途停掉 |
| 上下文已降级 | 会话被自动压缩过，细节只剩摘要 |

除「完成」外，其余四个都要在第 4 块末尾的未验证清单里点名。

### 第 3 块怎么写

每条证据占一行，三项齐：命令、输出摘要、是谁复跑的。

- 命令要能直接粘贴，带工作目录或绝对路径。
- 输出摘要写判定结果，比如 `31 pass / 0 fail`、`diff 为空`，不贴整段日志。
- 复跑分三种：独立验收成员跑过、只有实现者跑过、谁都没跑。第三种不算证据；第二种要在汇总里标「实现者自检」。

### 第 5 块怎么写

死路按结论级写，一行一条，形状是「试过 X，不行，因为 Y」。不写探索过程。

不可逆决策一条一记录，五个字段：
1. 背景：当时卡在什么上。
2. 备选：还考虑过什么。
3. 选的：最后选了哪个。
4. 依据：为什么是它。
5. 什么情况下推翻：什么信号出现就该翻案。

### 第 6 块里的遗留

Lead 拆活分为主目标、支撑、枝节：降了优先级的枝节与耗时验收落进一份独立的遗留问题清单 `.scratch/<effort>/leftovers.md`，五列：编号、问题、为什么现在不做、后面怎么查、什么时候回看。清单本身不进汇总正文。
第 6 块末尾只写三样：没解决的编号、一句话是什么、清单路径。整张表不贴过来。
清单在、里面一条都没有，写「遗留：无」；清单没拿到是另一回事，见下文「单独调用时怎么降级」。留空读者分不清是「没有」还是「漏了」。

## 原料怎么取：三层按顺序

三层，按顺序取，别跳级。上层够用就不下钻。

| 层 | 来源 | 取什么 |
|---|---|---|
| 1 | 收尾消息 | 结论、文件清单、验收输出、偏离规格四块，做骨架 |
| 2 | 工作日志 | `.scratch/<effort>/worklog-<mate>.md`，过程细节、死路、决策 |
| 3 | 会话日志 | 兜底，只在收尾消息缺字段或工作日志不存在时 |

### 第 1 层：收尾消息

成员收尾时，它最后那条消息随通知进你的上下文。大多数情况这一层就够写第 1、2、3 块。
有两种情况会缺：

- 上下文被压缩，早期成员的通知只剩摘要。
- 成员收尾前刚发过 `send_message`，收尾正文会被省掉。

缺的这部分派一个只读成员去捞：让它把原文原样带回来，你判断哪些进汇总。它的检索条件是 `session_id` 填你的会话 id（它自己拿不到这个 id，派活时直接写进 prompt），`surfaces` 同时带被遮蔽和只进日志两面：

```js
session_event_search({ session_id: '<你的会话 id>', query: '<成员名或交付物关键词>', surfaces: ['shadowed', 'log-only'] })
```

`query` 是必填的全文关键词，做的是字符串匹配，不是语义检索。写成员名或文件名最准。

这一步是业务面上唯一允许你自己做的一步，不是视情况：`session_id` 只有你手上有，成员拿不到；缺的只剩一两条时，派人的成本也大于收益。这两种情况你自己捞，其余一律派成员。

### 第 2 层：工作日志

路径固定 `.scratch/<effort>/worklog-<mate>.md`，格式见 lead-mode 的「工作日志与交接文档放哪」一节。头部状态摘要给第 2 块，下面的轮次记录给第 4、5 块。

文件不存在不算异常：说明该成员没按派活要求写日志，第 2 块状态照实写，第 4 块末尾清单点名。

### 第 3 层：会话日志下钻

只在「收尾消息缺字段」或「工作日志不存在」时用，**一个成员最多下钻一次**。

```js
session_event_search({ session_id: '<成员 id>', event_types: ['assistant/message'] })
```

成员 id 老一代由 `list_agents` 直接给出；新一代的 `list_agents` 只给名字和路径、不保证给 session id，拿不到就跳过这一层，照实写「未验证」。

两条限制：
- 跨 cwd 读不到。成员会话的工作目录必须和 Lead 相同，否则这条查不到东西。
- 下钻一次还不齐就写「未验证」，不要反复翻。

## 来源标记怎么挂

按证据类型挂，挂错类型等于没挂。

| 证据类型 | 挂什么 | 例子 |
|---|---|---|
| 改动 | `路径:行号` | `skills/team-digest/SKILL.md:38` |
| 验收 | 可粘贴命令 | `node --test test/*.test.mjs` |
| 决策 | 工作日志段名，或 `session-<id>#seq` | `worklog-skill-author.md 第 5 块` |
来源标记写的是位置，不复述内容。复制两份，改一份就有一份在骗人。
## 异常成员怎么处理

| 情况 | 第 2 块状态 | 额外动作 |
|---|---|---|
| 没交收尾消息 | 被打断 | 第 4 块末尾清单列出它负责的交付物 |
| 只有「已通过」「已修复」这类话 | 未验证 | 能派独立成员复跑就复跑，跑不了就照实写缺什么 |
| 工作日志没写 | 按实际交付判 | 第 4 块末尾清单点名「无工作日志」 |
| 被压缩过 | 上下文已降级 | 需要细节时下钻一次，结论降一档置信度 |
| 创建失败或始终没起来 | 卡住 | 单列一行，写清失败现象 |

## 宿主事实（当前行为，别按直觉推）

| 事实 | 后果 |
|---|---|
| `team_task_update` 的 `complete` 不能带结果载荷 | 任务板不是结果记录本，结论只能写进汇总 |
| `wait_agent` 只返回 `{timedOut}`（老一代还多一个 `noProgress`） | 它不带任何内容，别指望从返回值里拿到成员说了什么 |
| 宿主没有报告类工具 | 汇总只能自己组织，没有现成模板命令可调 |
| 压缩事件（`compaction/start` 等）都是 log-only | 检索必须显式带 `surfaces: ['log-only']`，否则查不到 |
| 成员上限 `maxMembers` 只有老一代可读（新一代拒绝这个配置键） | 老一代名字永不释放，创建失败也占一个上限名额；新一代读不到上限，别写一个假数字 |

## 写作口径

- 中文，短句，结论在前。
- 没实测的数字不写精确值，写「未验证」。
- 纯 markdown，零外部依赖。
- Obsidian、answer-me-with-html、dsh-context 一律「装了才用」，没装也要能写完。
- 术语固定五个：团队汇总、死路、产物、来源标记、遗留问题清单。不另造近义词。

## 单独调用时怎么降级

没有 lead-mode 的团队上下文时（用户直接调 `/skill team-digest`）：只写手上有的材料，别为了凑六块去猜。用户明确要，就不受上面两条触发条件限制。

先做什么：按 `.scratch/<effort>/worklog-*.md` 找工作日志，按 `reports/` 找同 effort 的旧汇总，拼出第 2、5 块。

缺原料怎么办：缺收尾消息的成员在清单里写「未验证：缺收尾消息」；没有 session id 就跳过会话日志层并说明缺哪层。不编造成员和数字。找不到 `.scratch/<effort>/leftovers.md` 写「未验证：缺遗留清单」，清单在但一条都没有写「遗留：无」——两种都不许写成「没有遗留」，那句话分不清材料缺还是确实没有。
停下来问：找不到 effort 目录、也没有任何成员收尾消息时，问用户要 effort 名或原料出处，别硬写一份空的。

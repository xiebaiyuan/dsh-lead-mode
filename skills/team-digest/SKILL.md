# 团队汇总：写什么、给谁看

成员各交一段收尾消息、各写一份工作日志；无人合并时，用户须自行翻阅多条通知，日后回看也需重新调查。本 skill 产出该合并文件，主要读者是日后回看的你，当场看懂只是副产物，不为版面好看多写内容。

## 什么时候写

给最终答复前判断，满足任一条即写：

| 条件 | 说明 |
|---|---|
| 本 effort 有 2 个以上成员 | 产出分散在多段消息中，需合并为单一入口 |
| 跨 2 轮以上 | 同一成员多轮或换过续作成员，过程分散在多轮里 |

不写的情况：单成员一轮完成、仅查询资料未改动、纯问答；不为单次调用产出团队汇总。

## 写到哪

`reports/<YYYY-MM-DD>-<effort>.md`，相对仓库根，单一路径。

- `<effort>` 沿用 `.scratch/` 下对应目录名，与工作日志同源，不另起命名。
- 扁平落盘：不新增目录层级，不加 `-v2`、`-final` 等后缀。
- 同一 effort 同一天只写一份：收尾时一次成型，不追加、不做增量、不设「晋升」步骤。
- 需进笔记库时，由外部为 `reports` 建软链，不改本落盘路径。
- 目录不存在则创建；无法创建（如只读挂载）时在最终答复中明确说明，不静默丢弃。

## 六块骨架

六块标题固定：不改名、不合并、不跳过；某块无内容时写「无」。

| 块 | 标题 | 写什么 |
|---|---|---|
| 1 | 结论 | 首行固定写 `主目标：达成/部分达成/未达成（N/M）`，随后一到两句写明完成情况与可用状态。不放清单 |
| 2 | 谁干了什么 | 表格：成员 / 交付物 / 状态 / 产物指针 |
| 3 | 验收证据 | 一条一行：可粘贴的命令 + 输出摘要 + 是谁复跑的（独立验收成员跑的最高级，仅实现者跑的不算） |
| 4 | 偏离与未验证 | 偏离规格的、只口头声称无证据的；末尾附未验证清单 |
| 5 | 死路与决策 | 结论级死路一行一条；不可逆决策一条一记录 |
| 6 | 未决与下一步 | 还没定的、下一轮第一件事、明确不做什么；遗留只写编号 + 一句话 + 清单路径，没有就写「遗留：无」 |

按以下骨架填写，标题保持逐字一致：
```markdown
# 团队汇总 · <effort>

## 结论

主目标：达成/部分达成/未达成（N/M）

## 谁干了什么

| 成员 | 交付物 | 状态 | 产物指针 |
|---|---|---|---|

## 验收证据

## 偏离与未验证

### 未验证清单

## 死路与决策

## 未决与下一步
```

第 4 块专放偏离规格的结论与无证据结论，不混入第 1、2、3 块；末尾未验证清单只写「谁、什么没验、缺什么证据」，不拿清单替代整块说明。

### 第 1 块首行怎么写

第 1 块首行固定写 `主目标：达成/部分达成/未达成（N/M）`（三选一），随后一到两句说明结果与可用状态：

- `M` 为开工定下的主目标判据总数，`N` 为已有可复跑证据通过的条数；只计主目标判据，不把遗留清单里的枝节混进分母。
- 示例：`主目标：达成（3/3）`、`主目标：部分达成（2/3）`、`主目标：未达成（0/3）`。
- 单独调用降级、缺少开工判据清单时，照实写 `主目标：未验证（缺主目标判据）`，不编造 `N/M`。

### 第 2 块的状态列

状态列限定五个取值，不扩展：

| 取值 | 什么时候用 |
|---|---|
| 完成 | 交付物在，且经过独立验收核验 |
| 未验证 | 交付物在，但仅有口头声称，缺可复跑证据 |
| 卡住 | 未完成，阻塞点仍在 |
| 被打断 | 被 `interrupt_agent` 或用户中途停掉 |
| 上下文已降级 | 会话被自动压缩过，早期细节只剩摘要 |

除「完成」外，其余四项均须在第 4 块末尾的未验证清单中点名。

### 第 3 块怎么写

每条证据占一行，三项齐全：命令、输出摘要、是谁复跑的。

- 命令可直接粘贴，附工作目录或绝对路径。
- 输出摘要写判定结果（如 `31 pass / 0 fail`、`diff 为空`），不贴整段日志。
- 复跑分三种：独立验收成员跑过、仅实现者跑过、无人跑过。第三种不算证据；第二种须在汇总中标明「仅实现者运行」。

### 第 5 块怎么写

死路写结论级，一行一条，格式为「试过 X，不行，因为 Y」，不展开探索过程。

不可逆决策一条一记录，五个字段：
1. 背景：当时卡在什么上。
2. 备选：还考虑过什么。
3. 选的：最后选了哪个。
4. 依据：为什么是它。
5. 什么情况下推翻：什么信号出现就该翻案。

### 第 6 块里的遗留

Lead 拆活分为主目标、支撑、枝节：降了优先级的枝节与耗时验收落入独立遗留问题清单 `.scratch/<effort>/leftovers.md`（五列：编号、问题、为什么现在不做、后面怎么查、什么时候回看；「后面怎么查」填可粘贴命令、文件路径，或可复现走查步骤 `对象 + 入口 + 判据`）。遗留项与第 1 块主目标判据分开记账，清单本身不贴入汇总正文。

第 6 块末尾只写三项：未解决编号、一句话说明、清单路径；不搬运整张表。

清单存在且零条记录时写「遗留：无」；未拿到清单则见下文「单独调用时怎么降级」。不可留空，避免读者分不清「没有」与「遗漏」。

## 原料怎么取：三层按顺序

按三层顺序取料，上层够用即止，不跳级下钻。

| 层 | 来源 | 取什么 |
|---|---|---|
| 1 | 收尾消息 | 结论、文件清单、验收输出、偏离规格四块，做骨架 |
| 2 | 工作日志 | `.scratch/<effort>/worklog-<mate>.md`，过程细节、死路、决策 |
| 3 | 会话日志 | 兜底，仅在收尾消息缺字段或工作日志不存在时使用 |

### 第 1 层：收尾消息

成员收尾时，其最后一条消息随通知进入你的上下文；多数情形凭这一层即可写出第 1、2、3 块。以下两种情形会缺：

- 上下文被压缩，早期成员通知仅剩摘要。
- 成员收尾前刚发过 `send_message`，通知中省略收尾正文。

缺漏部分派只读成员取回原文，由你筛选写入汇总。检索条件中 `session_id` 填你的会话 id（成员无法自取，须在派单 prompt 中给出），`surfaces` 同时带上被遮蔽与仅日志两面：

```js
session_event_search({ session_id: '<你的会话 id>', query: '<成员名或交付物关键词>', surfaces: ['shadowed', 'log-only'] })
```

`query` 为必填关键词，执行精确字符串匹配（非语义检索），填成员名或文件名最准。

此步属于只读核证据，是业务面上唯一允许你自己做的一步：`session_id` 仅你持有、成员拿不到，且只缺一两条时派人成本高于直接查看；其余情况一律派成员取回。

### 第 2 层：工作日志

路径固定为 `.scratch/<effort>/worklog-<mate>.md`（格式见 `lead-mode`「工作日志与交接文档放哪」）。头部状态摘要用于第 2 块，轮次记录用于第 4、5 块。

文件不存在不算异常，说明该成员未按要求记录；第 2 块按实际状态填写，并在第 4 块末尾清单点名。

### 第 3 层：会话日志下钻

只在「收尾消息缺字段」或「工作日志不存在」时启用，**每个成员最多下钻一次**。

```js
session_event_search({ session_id: '<成员 id>', event_types: ['assistant/message'] })
```

成员 id 在老一代由 `list_agents` 直接返回；新一代 `list_agents` 只给名称与路径、不保证含 session id，拿不到则跳过该层并照实写「未验证」。

两条限制：
- 跨 cwd 不可读：成员工作目录须与 Lead 相同，否则检索无结果。
- 下钻一次仍不齐则写「未验证」，不再反复检索。

## 来源标记怎么挂

按证据类型挂载，挂错类型视为未挂：

| 证据类型 | 挂什么 | 例子 |
|---|---|---|
| 改动 | `路径:行号` | `skills/team-digest/SKILL.md:38` |
| 验收 | 可粘贴命令 | `node --test test/*.test.mjs` |
| 决策 | 工作日志段名，或 `session-<id>#seq` | `worklog-skill-author.md 第 5 块` |

来源标记只写位置，不复述内容；复述两份则改一处即导致另一处失真。

## 异常成员怎么处理

| 情况 | 第 2 块状态 | 额外动作 |
|---|---|---|
| 未交收尾消息 | 被打断 | 第 4 块末尾清单列出其负责的交付物 |
| 仅有「已通过」「已修复」口头声称 | 未验证 | 能派独立成员复跑即复跑，否则照实写缺什么证据 |
| 未写工作日志 | 按实际交付判 | 第 4 块末尾清单点名「无工作日志」 |
| 会话被压缩过 | 上下文已降级 | 需要细节时下钻一次，结论降一档置信度 |
| 创建失败或始终未启动 | 卡住 | 单列一行，写明失败现象 |

## 宿主事实（当前行为，别按直觉推）

| 事实 | 后果 |
|---|---|
| `team_task_update` 的 `complete` 不带结果载荷 | 任务板不是结果记录本，结论只能写入汇总 |
| `wait_agent` 仅返回 `{timedOut}`（老一代多一个 `noProgress`） | 不携带任何成员消息，不从其返回值取结论 |
| 宿主无内置汇总工具 | 汇总由 Lead 按六块骨架自行组织，无现成模板命令可调 |
| 压缩事件（`compaction/start` 等）均为 log-only | 检索必须显式传 `surfaces: ['log-only']`，否则查不到 |
| 成员上限 `maxMembers` 仅老一代可读（新一代拒绝此配置键） | 老一代名字永不释放，创建失败同样占用一个成员上限；新一代读不到上限，不写猜测数字 |

## 写作口径

- 中文，短句，结论在前。
- 未实测的数字不写精确值，写「未验证」。
- 纯 markdown，零外部依赖。
- Obsidian、`answer-me-with-html`、`dsh-context` 一律「装了才用」，未装也能写完。
- 术语固定五个：团队汇总、死路、产物、来源标记、遗留问题清单，不另造近义词。

## 单独调用时怎么降级

脱离 `lead-mode` 团队上下文调用时（如用户直接运行 `/skill team-digest`）：仅凭现有材料落笔，不为了凑齐六块而猜测；用户明确要求时不受「什么时候写」两条门槛限制。

先找材料：按 `.scratch/<effort>/worklog-*.md` 收集工作日志，按 `reports/` 查找同 effort 历史汇总，拼出第 2、5 块。

缺原料时处理：缺收尾消息的成员在清单写「未验证：缺收尾消息」；缺 session id 则跳过会话日志层并注明缺失层；不编造成员与数字。找不到 `.scratch/<effort>/leftovers.md` 写「未验证：缺遗留清单」，清单存在但零条写「遗留：无」；两种情形均不写成「没有遗留」，以免混淆材料缺失与实际为零。

停下来问：找不到 effort 目录且无任何成员收尾消息时，向用户确认 effort 名称或原料来源，不凭空补写空汇总。

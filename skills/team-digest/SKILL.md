# 团队汇总

成员各交一段收尾消息，各写一份工作日志。收尾时没人合并，用户得自己翻 N 条通知，过一周想回看还得重新调查一遍。这份 skill 产出那份合并物。

主要用途是日后回看。当场看懂是它的副产物，不要为了「当场好看」多写。

## 什么时候写

给最终答复之前判断，满足一条就写：

| 条件 | 说明 |
|---|---|
| 本 effort 有 2 个以上成员 | 一人一段就要合并，否则用户得自己拼 |
| 跨 2 轮以上 | 同一成员多轮、或换过续作成员，过程散在多轮里 |

不写的情况：只有一个成员一轮干完、只查了资料没改动、纯问答。别为一次调用产出一份报告。

## 写到哪

`reports/<YYYY-MM-DD>-<effort>.md`，相对仓库根，单一路径。

- `<effort>` 用 `.scratch/` 下那个目录名，和工作日志同源，别另起一套命名。
- 不新增目录层级，不加 `-v2`、`-final` 这类后缀。
- 同一 effort 同一天只写一份。收尾时一次成型，不追加、不做增量、不设「晋升」步骤。
- 想进笔记库，自己给 `reports` 建软链，不要改路径。
- 目录不存在就建。建不了（只读挂载等）就在最终答复里说清楚，别悄悄丢。

## 六块骨架

六块标题写死：不改名、不合并、不跳块。某块没内容就写「无」。

| 块 | 标题 | 写什么 |
|---|---|---|
| 1 | 结论 | 做完了什么、能不能用，一到两句。不放清单 |
| 2 | 谁干了什么 | 表格：成员 / 交付物 / 状态 / 过程产物指针 |
| 3 | 验收证据 | 一条一行：可粘贴的命令 + 输出摘要 + 是不是 Lead 自己复跑过 |
| 4 | 偏离与未验证 | 偏离规格的、只口头声称没证据的 |
| 5 | 死路与决策 | 结论级死路一行一条；不可逆决策一条一记录 |
| 6 | 未决与下一步 | 还没定的、下一轮第一件事、明确不做什么 |

照这个骨架填，标题一个字都别改：

```markdown
# 团队汇总 · <effort>

## 结论

## 谁干了什么

| 成员 | 交付物 | 状态 | 过程产物指针 |
|---|---|---|---|

## 验收证据

## 偏离与未验证

### 未验证清单

## 死路与决策

## 未决与下一步
```

第 4 块是隔离区。「已通过」但拿不出证据的东西只能写在这里，不许混进第 1、2、3 块。

### 第 2 块的状态列

只有五个取值，别扩展：

| 取值 | 什么时候用 |
|---|---|
| 完成 | 交付物在，验收证据也核过 |
| 未验证 | 交付物在，但只有口头声称，没有可复跑的证据 |
| 卡住 | 没干完，阻塞点还在 |
| 被打断 | 被 `interrupt_agent` 或用户中途停掉 |
| 上下文已降级 | 会话被自动压缩过，细节只剩摘要 |

除「完成」外，其余四个都要在末尾「未验证」清单里点名。

### 第 3 块怎么写

每条证据占一行，三项齐：命令、输出摘要、是否复跑。

- 命令要能直接粘贴，带工作目录或绝对路径。
- 输出摘要写判定结果，比如 `31 pass / 0 fail`、`diff 为空`，不贴整段日志。
- 复跑分三种：Lead 自己跑过、只有成员跑过、谁都没跑。第三种不算证据。

### 第 5 块怎么写

死路按结论级写，一行一条，形状是「试过 X，不行，因为 Y」。不写探索过程。

不可逆决策一条一记录，五个字段：

1. 背景：当时卡在什么上。
2. 备选：还考虑过什么。
3. 选的：最后选了哪个。
4. 依据：为什么是它。
5. 什么情况下推翻：什么信号出现就该翻案。

## 原料怎么取

三层，按顺序取，别跳级。上层够用就不下钻。

| 层 | 来源 | 取什么 |
|---|---|---|
| 1 | 收尾消息 | 结论、文件清单、验收输出、偏离规格四块，做骨架 |
| 2 | 工作日志 | `.scratch/<effort>/worklog-<mate>.md`，过程细节、死路、决策 |
| 3 | 会话日志 | 兜底，只在收尾消息缺字段或工作日志不存在时 |

### 第 1 层：收尾消息

成员收工时，它最后那条消息随通知进你的上下文。大多数情况这一层就够写第 1、2、3 块。

有两种情况会缺：

- 上下文被压缩，早期成员的通知只剩摘要。
- 成员收工前刚发过 `send_message`，收尾正文会被省掉。

捞回来用 `session_event_search`，`session_id` 填自己的会话 id，`surfaces` 同时带被遮蔽和只进日志两面：

```
session_event_search({
  session_id: '<你自己的会话 id>',
  query: '<成员名或交付物关键词>',
  surfaces: ['shadowed', 'log-only'],
})
```

`query` 是必填的全文关键词，做的是字符串匹配，不是语义检索。写成员名或文件名最准。

### 第 2 层：工作日志

路径固定 `.scratch/<effort>/worklog-<mate>.md`。头部状态摘要给第 2 块，下面的轮次记录给第 4、5 块。

文件不存在不算异常：说明该成员没按派活要求写日志，第 2 块状态照实写，末尾清单点名。

### 第 3 层：会话日志下钻

只在「收尾消息缺字段」或「工作日志不存在」时用，**一个成员最多下钻一次**。

```
session_event_search({
  session_id: '<成员 id>',
  event_types: ['assistant/message'],
})
```

两条限制：

- 跨 cwd 读不到。成员会话的工作目录必须和 Lead 相同，否则这条查不到东西。
- 下钻一次还不齐就写「未验证」，不要反复翻。

## 证据指针怎么挂

按证据类型挂，挂错类型等于没挂。

| 证据类型 | 挂什么 | 例子 |
|---|---|---|
| 改动 | `路径:行号` | `skills/team-digest/SKILL.md:38` |
| 验收 | 可粘贴命令 | `node --test test/*.test.mjs` |
| 决策 | 工作日志段名，或 `session-<id>#seq` | `worklog-skill-author.md 第 5 块` |

指针指向已有产物，不复制正文。复制两份，改一份就有一份在骗人。

## 异常成员怎么处理

| 情况 | 第 2 块状态 | 额外动作 |
|---|---|---|
| 没交收尾消息 | 被打断 | 末尾清单列出它负责的交付物 |
| 只有「已通过」「已修复」这类话 | 未验证 | 能复跑就复跑，跑不了就照实写缺什么 |
| 工作日志没写 | 按实际交付判 | 末尾清单点名「无工作日志」 |
| 被压缩过 | 上下文已降级 | 需要细节时下钻一次，结论降一档置信度 |
| 创建失败或始终没起来 | 卡住 | 单列一行，写清失败现象 |

「未验证」清单不是第 4 块的替代品：第 4 块写偏离规格和无证据的结论，清单写「谁、什么没验、缺什么证据」。

## 宿主事实

这些是宿主当前行为，别按直觉推：

| 事实 | 后果 |
|---|---|
| `team_task_update` 的 `complete` 不能带结果载荷 | 任务板不是结果记录本，结论只能写进汇总 |
| `wait_agent` 只返回 `{timedOut, noProgress}` | 它不带任何内容，别指望从返回值里拿到成员说了什么 |
| 宿主没有报告类工具 | 汇总只能自己组织，没有现成模板命令可调 |
| 压缩事件（`compaction/start` 等）都是 log-only | 检索必须显式带 `surfaces: ['log-only']`，否则查不到 |
| 成员名额 `maxMembers` 由 profile 层设为 8 | 名字永不释放，创建失败也占名额 |

## 写作口径

- 中文，短句，结论在前。
- 没实测的数字不写精确值，写「未验证」。
- 六块标题写死，不许改名、不许合并、不许跳块。
- 纯 markdown，零外部依赖。Obsidian、answer-me-with-html、dsh-context 一律「装了才用」，没装也要能写完。
- 术语固定四个：团队汇总、死路、过程产物、证据指针。不另造近义词。
